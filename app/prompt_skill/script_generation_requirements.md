【技术要求】
- 视频总时长：约$effective_total_duration秒
- 所有分镜 duration 之和要尽量贴近$effective_total_duration秒，不要明显偏短或偏长
- 总时长不得超过$total_duration_max秒
- 每个分镜时长：$scene_duration_min-$scene_duration_max秒之间灵活调整；先评估动作节点、出场人数、对白/信息量、空间调度和情绪转折，再设定 duration。5-9秒用于单一建立/短反应/简单转场，10-18秒用于完整互动或一次明确推进，19-30秒仅用于多角色连续动作、复杂调度、重大揭示、冲突升级、反转或高潮
- duration 字段只能输出 $scene_duration_min-$scene_duration_max 的整数，禁止输出 $disallowed_duration_examples 或更大值
- 不同丰富度的分镜不得使用相同时长；只要总时长与上下限允许，最长与最短分镜至少相差2秒，4个及以上分镜至少使用3档时长，并让复杂度最高的分镜获得更多时长
- 禁止为获得更长 duration 重复动作、同义改写或填充无剧情作用的空镜；时长必须由可执行内容量决定
- 分镜数量：约$estimated_scene_count个，总数不得超过$max_storyboard_scenes个
- 时长分配：绝大部分时长用于情节发展与剧情推进（细致刻画角色/动作/心理/互动，节奏紧凑推向高潮）；开头与结尾要精简，不占用过多时长
- 结尾方式：可用钩子式结尾/突然收尾/开放式结尾/合家欢结尾等，按 tone 选择最契合的一种，收得利落有回味
- 剧情要求：有故事感、有起伏、按因果链推进、连贯不跳跃、符合客观规律
- 每个分镜都要写足环境空间/材质/关键物件、人物位置、动作、细微表演、眼神、情绪变化、互动结果、镜头调度、光影与剧情推进细节
- 每个分镜的 description 必须按连续秒段展开，从 0 秒开始并准确覆盖到该分镜 duration，推荐每段 2-5 秒；5-9秒至少2段，10-18秒至少3段，19-30秒至少4段。例如 duration=15 时可使用“0-3秒：...；3-7秒：...；7-10秒：...；10-15秒：...”，禁止时间缺口、重叠、倒退或越界
- 每个秒段必须具体写明人物所在位置及相互方位/距离、各自动作、表情、眼神、情绪、互动结果，以及镜头景别/角度/运动/焦点和环境光影变化；下一秒段必须承接上一秒段状态并产生新的剧情推进，不得使用“二人互动”“气氛紧张”“镜头推进”等空泛概括
- 每个秒段应按“触发动作 -> 身体/视线/表情反应 -> 互动或环境反馈 -> 新的可见结果”推进，写清动作起点、方向、速度/力度、接触对象和结束姿态；后一秒段必须从前一秒段最后一刻的站位、姿势、朝向、视线、接触关系、道具位置和镜头运动继续，不得重新介绍人物或重置动作
- 每个秒段保持 2-4 句可执行视觉描述，至少包含环境与空间锚点、人物动作、细微表演、镜头调度、光影/环境反馈和动作结果；抽象情绪必须转化为呼吸、眼神、表情、手指、重心、停顿等可见表演细节，并避免在短秒段中堆叠无法完成的动作
- 成人剧情镜头禁限：禁止男性阴茎或男性生殖器官特写，禁止口交镜头及口部接触生殖器官的动作，禁止性交插入过程中的生殖器官/插入部位/解剖细节特写；亲密剧情只可用中远景、侧背面、面部表情、眼神、上半身/手部动作、轮廓、光影与环境反应表达
- 成人剧情不得用“抽插”“反复插入”“下身撞击”“活塞式动作”等机械性性交动作反复填充秒段，也不得跨多个秒段/分镜换词复述同一亲密动作；应把重点转向人物关系与情绪变化、面部/眼神、呼吸、手部、肩背姿态、衣物/床品和环境反馈
- 跨分镜必须保持视觉风格、主色调、白平衡、主光方向、阴影、曝光和镜头语言相对统一；同一连续场景还要保持人物视线、运动方向、空间轴线、相对站位及道具位置可衔接，只有明确的时间/地点/光源变化才允许有依据地渐进改变
- description 只能写画面、环境、动作、神态和镜头，不得写直接对白、引号对白、台词或旁白；所有人物说出口的话、旁白和内心独白必须全部放入 dialogue
- dialogue 要根据剧情自然生成，符合角色性格和当前情绪情境，数量适量；在关键情绪/转折/冲突/信息推进分镜输出，每个有对白的分镜通常 1-2 行短对白即可，非必要分镜可以为空；每次对白必须单独一行，角色说话格式为“[角色名]：对白内容”，旁白格式为“旁白：内容”
- 对白内容里绝大多数情况下不要直呼对方角色/人物的名字：当该分镜同一布景中出场角色为 1-2 人时，对白内容须去掉被称呼者的名字（例：“小李，我们现在去哪？”改为“我们现在去哪？”），仅保留行首“[角色名]：”作为说话人标识；只有当同一分镜同一布景中同时出现 3 人或以上时，才允许在对白内容中叫出对方角色/人物的名字
- 所有分镜叙事文本中的角色名必须用半角方括号标记，例如 `[小明]`、`[黑鹰]`、`[铃铛]`，避免动物或物品式姓名被图片/视频模型误解；此规则适用于 description、dialogue、character_description、voice_description、camera_angle。characters.name、characters_present 和 character_outfits 的键仍必须使用不带括号的原始姓名
- 每个分镜都必须明确输出 time_of_day 和 weather 字段，例如白天/夜晚、晴天/雨天，并与分镜内容保持一致；scene_state 字段必须位于 description（场景描述部分）之前，且只能包含时间与天气两类信息，推荐格式为“time_of_day，weather”，例如“深夜，晴天”“黄昏，沙尘天”；不得包含灯光、气味、情绪氛围、剧情发展、角色动作、角色状态、战斗痕迹、血污、破坏或临时道具
- 每个角色设定都必须完整输出 gender / age / nationality / face_features / hairstyle / body_features / clothing / personality / identity_background；这些字段会持久化并应用到后续生图/生视频，必须稳定、具体、前后一致
- character_outfits 是可跨分镜复用的稳定造型 ID；仅当主服装类别/轮廓、主色、固定配饰、发型结构、裸露层级或明确穿脱关系相对默认 clothing/hairstyle 发生明显变化时，才输出对应角色条目
- character_outfits 的描述必须只包含稳定造型，例如“玄色窄袖劲装外罩暗红短披风，乌黑长发以红绳高束成马尾”“银色露背舞会礼服，长波浪发盘成低髻”“只穿黑色蕾丝内衣，披肩长发”；禁止写入动作、伤口、血污/妖血、雨水/汗水/湿透、泥污、局部撕裂/破损、褶皱、衣料贴身、发丝黏连/凌乱、皮肤纹路、光影或镜头信息
- 当分镜内容、description、character_description 或剧情意图包含裸露、暧昧身体部位或类似意思时，必须为相关角色生成 character_outfits 条目；不得仅写在 description 或 character_description 中
- 若角色在本分镜的装扮与默认 clothing、默认 hairstyle 一致，character_outfits 必须输出空对象或省略该角色条目；不得把通常装扮、默认发型重复写入 character_outfits
- 血污、湿润、伤口、局部破损、尘土和发丝凌乱等动态状态仍须在 description / character_description 中连续承接，但它们不得改变 character_outfits 或触发新的角色装扮图
- 同一角色沿用同一稳定造型时，后续分镜必须逐字复用首次描述；不得因语序、同义词、程度词或动态状态创建近似装扮。只有服装类别/轮廓/主色、固定配饰、发型结构、裸露层级或穿脱关系实质变化时，才建立新的 character_outfits 描述
- 输出前先在心中规划每个分镜的唯一叙事功能（诱因/追逐/发现/误会/反转/抉择/高潮/收束等），不要把规划过程写进 JSON
- 输出前还要在心中维护逐镜状态账本：上一镜结果、本镜入场状态、本镜新增变化和本镜出场状态；至少跟踪每名角色的位置/朝向/姿势、动作、道具、装扮与伤污湿润状态、情绪强度、关系、当前目标、已知信息和未知信息
- characters 中姓名、年龄、性别、国籍、面容、默认发型、身材、肤色、声音和身份背景是全片固定身份锚点，不得在不同分镜漂移、互换或转移给其他角色；行为、对白与情绪变化必须符合 personality、identity_background、当前目标和知识边界（已知/未知信息），反常选择必须有前因和可见触发
- 相邻分镜必须形成“上一镜结果 -> 下一镜反应/后果”的因果承接；除最后一镜外，每段 description 结尾都要给出能带到下一镜的动作、视线、情绪或镜头转场钩子
- 下一镜第一个秒段必须先响应上一镜最后秒段的具体承接点，再产生新的结果；不得无解释地跳过关键动作、突然换地点/时间、让离场角色瞬间返回、让角色提前知道未揭示信息，或让伤口、污渍、湿润、妆容、饰品和随身道具凭空消失
- 每个分镜必须提供新的动作结果、信息揭示、情绪变化或空间/时间状态；即使同一布景同一人物连续出现，也不能复述上一镜已经完成的动作、对白和画面状态
- 所有分镜的出场角色总数与角色设定共用同一个上限，最多$max_characters个；凡是出现在 characters_present 的角色，都必须在 characters 中给出设定
- 每个布景设定都必须输出 scene_features 数组，写清该场景的稳定特征，例如灯光、陈设、建筑材质、空间布局、环境符号
- 必须输出 tone 字段，明确剧本背景基调，并让剧情、氛围、镜头与对白贯穿该基调；用户已指定基调/题材时须尊重用户
- 必须输出 era 字段，明确剧本所处的时代/年代，并让服化道、场景陈设、科技水平、社会风貌、语言用词都契合该时代；用户已指定时代/年代时须尊重用户
- 每个角色都必须输出 nationality（国籍/族裔/地域身份）、hairstyle（默认发型）、body_features（身材特征）、personality（性格侧写）、identity_background（身份背景）；主角尤其要立体可信、避免脸谱化
- 真正不同的稳定角色造型必须使用区别明显的描述；同一稳定造型则必须逐字复用，不得为逐镜动态状态改写。输出 JSON 时每个分镜必须先输出 character_outfits 和 scene_state，再输出 description
